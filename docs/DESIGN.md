# UI 设计规范（Neobrutalism）

> 设计目标：新粗野主义，强调可读性、可点击反馈、强对比。

## 1. 视觉原则

- 组件必须有明确边界（粗边框）。
- 交互必须有明显反馈（悬停位移、阴影变化）。
- 信息层级优先于花哨动效。
- 保证移动端和桌面端都可读。

## 2. 设计 Token

| 用途 | 色值 |
|------|------|
| 主文字 | `#121212` |
| 主背景 | `#f7f2e9` |
| 强调黄 | `#ffdc5e` |
| 强调蓝 | `#6be7ff` |
| 危险红 | `#ff7171` |
| 成功绿 | `#a0ff61` |
| 卡片白 | `#ffffff` |

| 用途 | 值 |
|------|---|
| 标准边框 | `2px solid #121212` |
| 强边框 | `3px solid #121212` |
| 小阴影 | `2px 2px 0 #121212` |
| 大阴影 | `6px 6px 0 #121212` |
| 圆角 | `8px / 10px / 12px / 14px` |

## 3. 字体与排版

- 标题/按钮主字体：`'Arial Black', 'Segoe UI', sans-serif`
- 内容文字：`'Segoe UI', sans-serif`
- 标题字重：`800-900`
- 正文字重：`600-700`
- 最小字号不低于 `11px`

## 4. 组件规则

- 按钮：必须有边框 + 阴影 + hover 位移。
- 表格：表头固定、长表支持横向滚动。
- 弹窗：必须可取消，必须有清晰主按钮。
- 任务状态：统一在"全局控制条"显示，不依赖页面位置。

## 5. 响应式规则

- Popup 宽度固定但内部允许内容换行。
- Dashboard 在窄屏时优先保证横向滚动可用。
- 任何关键按钮不可被裁切或遮挡。

## 前端开发规范

> 作用：统一插件前端视觉、交互和布局规则，减少"同功能不同样式"问题。
> 主参考：`docs/DESIGN.md`、`docs/product/APP_FLOW.md`

### 1. 设计基线

- 风格：Neobrutalism（新粗野主义）
- 核心原则：强对比、强边界、强反馈、低歧义
- 禁止：无边框浅灰按钮、无状态反馈、遮挡核心内容

### 2. Design Tokens（固定值）

- 文字：`#121212`
- 主背景：`#f7f2e9`
- 强调黄：`#ffdc5e`
- 强调蓝：`#6be7ff`
- 危险红：`#ff7171`
- 成功绿：`#a0ff61`
- 边框：`2px solid #121212`（标准）、`3px solid #121212`（强调）
- 阴影：`2px 2px 0 #121212`（小）、`6px 6px 0 #121212`（大）
- 圆角：`8/10/12/14px`

### 3. 关键组件规范

#### 3.1 页面浮动按钮组（content 注入）

- 详情页按钮：固定在右上，不遮挡点赞/评论区统计。
- 博主页按钮：固定悬浮，不插入主内容容器，避免破坏页面布局。
- 小屏（≤1200px）：允许换行并收窄最大宽度。

#### 3.2 全局任务控制条

- 固定右下，可在列表页和详情页持续可见。
- 必须包含：进度文案、暂停/继续、停止。
- 状态文本必须明确当前阶段（扫描/下载/采集中）。

#### 3.3 弹窗

- 必须有取消路径，不允许不可关闭弹窗。
- 主按钮与次按钮视觉区分清晰。
- 弹窗叠层不超过 1 层，禁止双弹窗重叠。

#### 3.4 Dashboard

- 表格必须支持横向滚动。
- 长文本显示截断 + title 全量提示。
- 默认按 `createdAt` 倒序，支持切换升序。

### 4. 交互与反馈规范

- 所有耗时任务都要显示"正在进行中"状态。
- Toast 需节流，防止高频刷新导致卡顿。
- 错误提示用用户语言，不直接抛技术栈报错。

### 5. 响应式与可用性

- 关键操作按钮不能被页面原生元素遮挡。
- 组件最小可点击高度 ≥ `32px`。
- 窄屏下优先保留可操作性，再保留视觉完整性。

### 6. 变更要求

- 每次改 UI 前先更新对应选择器和布局策略到 `docs/SELECTORS.md`。
- 每次改 UI 后补充 `docs/product/TEST_CHECKLIST.md` 的回归项。
- 任何"视觉改造"不得改变既定用户流程（见 `docs/product/APP_FLOW.md`）。
