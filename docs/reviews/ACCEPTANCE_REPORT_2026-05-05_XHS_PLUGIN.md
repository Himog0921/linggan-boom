## 本轮发现并修复的问题

### 1. 工作台同步的部分成功结果被误判成失败

自动测试发现：当一批数据已经成功同步，但后续批次失败时，插件会把整次同步标为失败。

影响：

- 用户可能看到失败提示，但实际上前面已有数据成功进入工作台。
- 这会让验收和排查变得不可信。

处理：

- 已调整为：只要已有批次成功，就保留成功结果，同时标记为 `partial`，并带上后续失败原因。

### 2. 暂停中的任务被停止时可能卡住

自动测试发现：任务处于暂停状态时，如果直接停止，内部等待没有被释放，测试会挂起。

影响：

- 用户看到的是任务停不干净或后续状态不刷新。
- 工作台任务执行链路也可能被拖住。

处理：

- 已调整为：暂停中收到停止指令时，先解除暂停等待，再完成停止流程。

### 3. 工作台工位类型提示不够直观

实机验收发现：当前浏览器是监控工位时，插件会正确拒绝人工任务，但提示偏技术化，用户容易误判为接单失败。

处理：

- 已把配置页工位说明改成明确提示：监控工位只接监控中心任务，手动采集工位只接采集控制台任务。
- 已把 `ACCOUNT_PURPOSE_MISMATCH` 的不接单提示改成普通用户能直接理解的说明。

### 4. 插件刚更新后的刷新提示不够明确

实机验收发现：插件刚更新后第一次点击采集，会提示刷新页面。原提示没有说明刷新后可以继续做什么。

处理：

- 已把提示改为：刷新当前页面后再点一次，刷新后即可继续。
