## 模块 1：小红书主链路

### P0 问题（优先修复）

#### 1.1 博主采集字段缺失（头像、简介、粉丝/获赞为 0）
- **2026-04-20 回写**：已修复。当前实现已优先拆包 `userPageData._rawValue / userInfo._rawValue`，并在 `authorCollector.js` 中补齐 `basicInfo / userInfo / DOM` 多路 fallback，旧问题可关闭。
- **现象**：博主页采集后，头像无预览，简介为空，粉丝和获赞数据显示为 0
- **根因推测**：`SELECTORS.md` 中博主页选择器验证日期接近 30 天过期线，页面结构可能已变化
- **修复方向**：重新探查小红书博主页 DOM 结构，更新 `authorCollector.js` 和 `SELECTORS.md`

### P1 问题

#### 1.2 单篇笔记媒体下载未打包
- **现象**：图片是逐个文件分散下载，缺少按标题命名打包成 ZIP 的体验
- **修复方向**：增加 ZIP 打包下载能力，文件名关联笔记标题
- **2026-04-20 回写**：第一阶段已落地。当前 `noteMediaDownload.js` 已在小红书单篇笔记链路改为汇总图片/视频后下载单个 ZIP，ZIP 文件名会带 `noteId + title`，内部文件沿用 `图_01 / 标题.mp4` 命名；同时摘要会补 `zipped / zipName`。剩余缺口主要是实机确认大视频走 `fetchBinaryAsDataUrl` 打包路径时的稳定性。

#### 1.3 评论「全部展开」未触发「展开更多回复」
- **现象**：选择「全部展开」深度模式时，第三层及以后的子评论未采集到
- **根因推测**：「展开更多回复」按钮未被 DOM 操作触发，仅处理到二级
- **修复方向**：修正 `commentCollector.js` 中的展开按钮识别和触发逻辑
- **2026-04-20 回写**：第二阶段已落地。当前评论 API 主链路会主动补拉主评论之外的更多回复；DOM fallback 中 `expandAllReplies()` 也会在每轮点击后重新扫描 `div.show-more`，递归处理多层“展开更多回复”。本轮继续补了“API partial 且页面仍有 `show-more` 时，不要过早短路为完成，而是沿 DOM 继续续采”的 guard，并让 DOM 续采复用已有 API 评论结果，避免从零开始。新增 `tests/xhs-comment-expand.test.mjs` 与 `tests/xhs-comment-collector-state.test.mjs` 作为回归证据。剩余缺口主要是实机复验不同页面形态。

#### 1.4 评论图片区下载过快 + 暂停无扫描进度
- **2026-04-20 回写**：第一阶段已落地。当前评论图片区在扫描/打包暂停与继续时，会显式保留 `已扫描 X 张图片 / 已完成 X/Y 张` 上下文，不再只剩“扫描已暂停 / 继续扫描中...”；剩余缺口主要是实机确认节奏感与更细的安全感反馈。
- **现象**：下载速度过快，用户没有安全感；暂停后任务控制台不显示「已扫描 X 张图片」
- **修复方向**：增加适度延迟/进度反馈；暂停时保留已扫描数量上下文

#### 1.5 批量任务暂停后丢失进度上下文
- **2026-04-20 回写**：第一阶段已落地。当前共享任务控制台在暂停态会自动补上进度摘要（如 `已处理 X` / `X/Y`），不再只剩“已暂停”；同日已补齐 XHS 批量任务暂停 / 继续时保留最近一次进度摘要的代码缺口。剩余缺口主要是 Top N 点赞数、评论实际总数等更细粒度上下文，以及跨页面实机复验。
- **现象**：暂停后只显示「已暂停」，看不到已采多少条、扫描了多少条
- **修复方向**：任务控制台在暂停态保留当前进度摘要

#### 1.6 Top N 排序黑盒感
- **现象**：扫描过程中看不到各笔记的点赞数，无法确认排序逻辑
- **修复方向**：在任务控制台增加「当前扫描笔记」的点赞数展示，或增加排序结果预览

#### 1.7 批量评论无评论总数显示
- **现象**：上限 20 条但只有 7 条时，用户无感知
- **修复方向**：任务控制台显示「当前笔记实际评论数 X 条」

#### 2.1 Dashboard 评论 tab 无分页 + 列宽灾难
- **2026-04-20 回写**：本轮已完成分页、评论列宽收口、紧凑链接动作按钮，以及小红书评论“作品打开优先使用 `rawUrl/xsec_token` 分享链接”的补修；用户当日实机反馈已确认 Dashboard 评论页优化成功。剩余“无虚拟滚动”仅保留为后续体验债，不再按 P0 阻塞本轮收口。
- **现象**：4265 条评论一次性铺开，tab 切换卡顿；评论 tab 列宽被技术 ID 侵占，「内容」列可读性差
- **修复方向**：
  - 增加分页或虚拟滚动
  - 重构评论 tab 列宽：隐藏根评论 ID/父评论 ID 到展开详情，加宽「内容」和「作者」列

#### 2.2 博主 tab IP 属地字段混入简介内容
- **2026-04-20 回写**：已修复。该问题与 1.1 同源，当前博主采集已将 `description / ipLocation` 分字段提取，旧问题可关闭。
- **现象**：某博主 IP 属地显示为「广东来加入我的原生家庭训练营」（实为简介内容）
- **根因推测**：数据映射错误，字段偏移或选择器失效
- **修复方向**：修复 `authorCollector.js` 的字段提取逻辑

### P1 问题

#### 2.3 批量删除后勾选计数未清零
- **2026-04-20 回写**：已修复。当前删除完成后会同步清理 `selectedIds` 并刷新当前 tab，旧问题可关闭。
- **现象**：批量删除后，顶部「已勾选 X 条」计数未自动清零，需刷新才恢复
- **修复方向**：删除后同步更新 `selectedIds` 和 UI 计数

#### 2.4 同步到工作台反馈不完整
- **2026-04-20 回写**：已修复。当前 UI 会展示导入数、跳过数，以及后端返回的失败原因/明细摘要，旧问题可关闭。
- **现象**：同步成功后没有显示导入数量、跳过数量、失败原因
- **修复方向**：解析服务器返回的 `meta` 信息，在 UI 中展示完整结果

#### 2.5 笔记 tab 链接列被截断且无感知
- **2026-04-20 回写**：已修复。当前 Dashboard 已将 `notes / comments / authors` 的链接型单元格统一为紧凑可点击动作，并通过 `title` 暴露完整 URL；同时评论 tab 的“小红书作品 → 打开”已改为优先消费评论记录里的 `rawUrl/xsec_token` 分享链接，避免点击规范链接时落入安全限制 `300017`，旧问题可关闭。
- **现象**：「链接」列只显示「htt」，没有 tooltip 或可点击图标
- **修复方向**：链接列改为可点击图标，hover 显示完整链接

## 模块 3：抖音主链路

### P0 问题

#### 3.1 抖音综合搜索页批量视频/评论失效
- **2026-04-20 回写**：已定位根因为“综合搜索混用 captured/API 顺序，而不是按页面可见顺位”；当前代码已切到“DOM 可见顺位优先 + API aweme hydrate”，并让搜索批量视频在命中 `aweme` 时直接走 `collectDouyinVideoByAweme`，避免同批新记录再出现“无媒体预览 / 话题为空”的瘦记录。该问题仍待综合搜索页实机复验后再关闭。
- **2026-04-20 反馈补记**：最新实机反馈已确认“媒体预览 / 话题字段缺失”问题修复成功，但综合搜索页顺位仍未严格对齐当前页面结果，因此 3.1 继续保留为未关闭待办。
- **现象**：综合搜索页发起批量任务失败（沙漏 badge 显示），视频搜索页正常
- **根因推测**：综合页与视频页 DOM/API 结构不同，当前仅适配了视频搜索页
- **修复方向**：探查综合搜索页的作品列表加载方式，增加分支适配

#### 3.2 抖音评论图片区下载抓错图片来源
- **2026-04-20 回写**：已修复。当前评论图片区优先使用评论 `image_list` 里的 `origin_url / download_url`，并补了 MIME type 校验，旧问题可关闭。
- **现象**：扫描的不是评论区图片，下载的文件格式异常（`image` 类型无法打开）
- **根因推测**：图片选择器范围过宽，抓到了页面其他位置的图片资源
- **修复方向**：收紧选择器，确保只提取评论 `image_list` 中的高清 URL

#### 3.3 抖音单条评论采集有跳失
- **2026-04-20 回写**：已修复。当前已补热榜/最新双轮采集、三级回复递归、空评论 ID fallback 与连续空页才停止，旧问题可关闭。
- **现象**：部分评论未采集到，存在遗漏
- **根因推测**：API 翻页/截断逻辑有边界问题，或 cursor 处理不完整
- **修复方向**：审查 `commentCollector.js` 的抖音评论接口翻页和去重逻辑

### P1 问题

#### 3.4 从视频弹层页返回博主页后插件卡片恢复延迟
- **现象**：返回博主页后，右侧插件功能卡片切换有延迟/卡顿
- **修复方向**：优化页面切换检测和 UI 注入时机

#### 3.5 博主采集无头像预览（抖音+小红书）
- **2026-04-20 回写**：已修复。Dashboard authors tab 当前已增加头像列并显示缩略图，旧问题可关闭。
- **现象**：抖音和小红书的博主 tab 都缺少头像列
- **修复方向**：在 Dashboard 博主 tab 增加头像缩略图列

#### 3.6 停止/完成后缺少最终汇总反馈
- **2026-04-20 回写**：第一阶段已落地。当前 `idle / done` 终态会保留 3 秒结果摘要；抖音批量 stopped 文案已补 `成功 X/Y` 与评论总数，小红书单条评论与评论图片区也会保留最终摘要。剩余缺口主要是更多链路的成功/失败细项统一。
- **现象**：任务停止或完成后，只显示「已停止」，没有「实际采了多少条、成功多少、失败多少」的汇总
- **修复方向**：任务结束/停止后，控制条保留 3 秒显示结果摘要

## 模块 4：UI/UX 与交互细节

> 设计规范：`docs/DESIGN.md`（Neobrutalism 风格）已确认，以下问题均为「风格正确但执行不统一」的范畴。

### P0 问题

#### 4.1 图标系统混乱（全是 Emoji，无统一风格）
- **2026-04-20 回写**：已修复。当前运行时源码已不再使用系统 Emoji 作为功能图标；Popup 主题切换中的残留 emoji 也已改为纯文字按钮，旧问题可关闭。
- **现象**：所有功能图标使用系统 Emoji，不同平台渲染效果不可控，视觉重量差异大
- **具体例子**：
  - 数据面板：📊（彩虹渐变）
  - 快速导出：💾（复古软盘）
  - 采集视频：📥（收件箱）
  - 下载视频：⬇️（蓝色箭头）
  - 评论图片：🖼️（风景相框）
- **修复方向**：引入一套统一的 SVG 图标库（如 Phosphor 或 Tabler Icons），替换所有 Emoji 图标

#### 4.2 弹窗主按钮文案不统一
- **2026-04-20 回写**：已修复。当前确认弹窗主动作已统一为“开始采集”，旧问题可关闭。
- **现象**：同一个确认动作，按钮文案有 4 种变体：「开始采集」「开始批量采集」「开始批量评论」「开始」
- **修复方向**：统一为「开始采集」

### P1 问题

#### 4.3 「当前内容」区块的无效重复
- **2026-04-20 回写**：已修复。当前若页面没有可用的单条操作，Popup 会折叠成单条空态提示，不再显示两颗含义重复的禁用按钮，旧问题可关闭。
- **现象**：页面不支持单条操作时，两个大按钮显示完全相同的文案（如「当前页不支持」或「先打开笔记页」）
- **修复方向**：若当前内容无可用操作，隐藏该区块或用一条顶部文字提示替代

#### 4.4 弹窗标题格式不统一
- **2026-04-20 回写**：已修复。当前批量弹窗标题已统一为“批量采集笔记 / 批量采集评论 / 批量采集视频”，旧问题可关闭。
- **现象**：「批量采集视频」「批量采集评论」「批量笔记设置」「批量评论设置」混用
- **修复方向**：统一为「批量采集视频」「批量采集评论」「批量采集笔记」

#### 4.5 Popup 数据 tab 字体/对齐不统一
- **2026-04-20 回写**：已修复。当前数据 tab 已补 section heading、账号数 badge、tabular nums，对 Cookie/账号区块和状态 badge 的字号/对齐做了一轮统一，旧问题可关闭。
- **现象**：说明文字字号/字重不一致；「2 个账号」数字对齐和字重与左侧标题不匹配；「已配置」badge 字号偏小
- **修复方向**：统一数据 tab 的字体层级和对齐规则

#### 4.6 输入框 placeholder 风格不一致
- **2026-04-20 回写**：已修复。Popup 侧输入框 placeholder 已统一为中低对比度灰色，新增账号限额也改成留空 + placeholder，不再默认预填数字，旧问题可关闭。
- **现象**：有的 placeholder 颜色偏深（几乎与输入文字同等明度），有的输入框直接预填数字而不是 placeholder
- **修复方向**：统一 placeholder 为中低对比度灰色；数字输入框统一保持空值 + placeholder

### P2 问题

#### 4.7 禁用按钮颜色语义混淆
- **2026-04-20 回写**：已修复。Popup 禁用态按钮当前统一为独立灰语义，不再保留主操作色的半透明残影，旧问题可关闭。
- **现象**：红色既代表「主操作」（采集视频），又代表「不可用」（先打开笔记页）
- **修复方向**：禁用态统一改为「灰底黑字」或「白底灰字」，与品牌操作色区分

#### 4.8 Checkbox 样式与整体设计语言脱节
- **2026-04-20 回写**：已修复。Popup 批量弹窗中的 checkbox / radio 已改为粗边框、自定义勾选样式，与现有 Neobrutalism 边框语言对齐，旧问题可关闭。
- **现象**：所有 checkbox 是浏览器原生细边框小方块，与 Neobrutalism 的粗边框强阴影风格不符
- **修复方向**：自定义 checkbox 样式，增加粗边框和统一尺寸

#### 4.9 任务控制台状态 badge 与实际进度不同步
- **2026-04-20 回写**：搜索页任务 badge 长期停在“准备中”的那一类问题已修复。当前 `taskUi` 在出现“采集 / 处理 / 展开 / 拉取 / 写入”等执行态文案时，会优先识别为“进行中”，不再被 `(current === 0 && total > 0)` 这类启动条件长期压回“准备中”。本条剩余缺口主要收敛为终态 badge 在少数链路下仍可继续优化。
- **现象**：24/24 仍显示「进行中」；12/12 仍显示「扫描中」
- **修复方向**：`current >= total` 时状态自动切换为「处理中」或「即将完成」
