# 验收检查清单

> 每次修改代码后，按对应功能的清单逐项验收。
> 验收格式：**操作 → 预期看到什么**
> 关联文档：[PRD.md](PRD.md) · [APP_FLOW.md](APP_FLOW.md)

---

## 当前验收分层（2026-04-02）

- 稳定主链路：
  小红书单篇/批量/评论/博主/评论图片区，抖音单条视频、分享触发采集、博主页/搜索页批量视频、博主页/搜索页批量评论。
- 重点回归链路：
  抖音单条评论、抖音评论图片区下载、抖音数据面板二次下载长时效、跨页面暂停/继续/停止、内容工作台自动接单闭环。
- 使用原则：
  “代码里有实现”不等于“已验收完成”；接手期优先把重点回归链路跑通，再把结果同步回本清单。

## 14. 内容工作台自动接单闭环验收（2026-04-10）

| # | 操作 | 预期结果 |
|---|------|---------|
| 14.1 | 在插件设置中填入工作台地址并启用工作台连接 | Background 开始轮询待执行任务；未启用时不应认领任务 |
| 14.2 | 在内容工作台创建一条与当前页面匹配的 `pending` 任务 | 插件会在轮询周期内自动发现该任务 |
| 14.3 | 当前浏览器存在匹配平台和页面上下文的 tab | 插件先做能力检查；只有页内任务真正启动并创建本地 `collectionRun` 后，才把任务推进到 `dispatched / running` |
| 14.3a | 远程批量任务在页内启动前就报错（如本地数据库不可用） | 内容工作台不能假装“已接单成功”；本轮应直接失败并保留可读错误 |
| 14.3aa | 小红书 `detail_probe` 任务拿到的是可直开的详情页（如 `discovery/item` 或已验证的签名详情页） | 插件应直接调用“采集当前笔记”这条单篇采集链，不再先绕到作者页；工作台日志里应看到真实笔记结果回传 |
| 14.3b | 小红书 `detail_probe` 任务来源是作者页卡片里的 `user/profile/.../noteId` 裸链接 | 插件应改走“作者页接力”路径：新开页时直接打开作者主页根地址，只保留目标 noteId，再点开这篇作品做单篇采集；如果原始链接已带 `xsec_token`，则必须继续保留签名直开 |
| 14.3c | 本地插件库或当前浏览器里已经存在同一篇小红书内容的签名分享页 | 插件应优先复用这条已验证可打开的入口，而不是继续新开裸 `/explore/{noteId}` 链接 |
| 14.3d | 当前浏览器里混有没真正接住插件的旧小红书 tab | 派单能力检查应自动跳过坏页并继续尝试下一张，不应因为第一张坏页直接整轮失败 |
| 14.4 | 任务进入运行态后查看工作台任务详情 | 能看到 `pluginRunId`、`progress`、`resultSummary` 开始回写 |
| 14.5 | 任务正常完成 | 工作台状态推进到 `completed`，结果摘要与插件结果包一致 |
| 14.6 | 任务失败或页面上下文不匹配 | 工作台保留 `pending` 或进入 `failed`，并有可读错误；不应误认领到错误页面 |
| 14.6a | 任务停在 `dispatched` 但 45 秒内一直没有本地运行记录 | 插件应自动把该任务标成失败并释放，不能让队列长期挂住 |
