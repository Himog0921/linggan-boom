# 灵感爆爆爆 — 用户操作流程

> 关联文档：[BEGINNER_GUIDE.md](BEGINNER_GUIDE.md) · [PRD.md](PRD.md) · [TEST_CHECKLIST.md](TEST_CHECKLIST.md)

## 1. 主流程总览

1. 用户打开小红书或抖音页面。
2. Popup 先显示当前平台和页面场景，告诉用户此页适合执行什么任务。
3. 用户在“当前内容 / 批量任务 / 工具区”中选择对应动作。
4. 任务状态卡统一显示准备中、扫描中、下载中、暂停中等阶段。
5. 页内长任务会使用统一的右下任务控制台和顶部通知条，避免平台之间出现两套完全不同的反馈方式；其中控制台卡片结构统一，但平台标题与按钮动作必须跟随当前站点。
6. 采集完成后，在 Dashboard 中查看、筛选、导出或再次下载媒体。
7. 若已启用内容工作台连接，插件还会在 Background 中轮询可执行的 `pending` 采集任务，并在匹配页面上自动接单。

## 2. 小红书单篇笔记采集流程

1. 进入笔记详情页，点击“采集笔记”。
2. 插件读取笔记内容和媒体链接并保存到本地。
3. 插件提示是否下载媒体文件。
4. 用户确认后，插件下载图片/视频。

成功结果：页面提示采集成功，数据面板出现新记录。  
失败结果：页面提示采集失败，并显示可读错误信息。

## 3. 小红书单篇评论采集流程

1. 进入笔记详情页，点击“采集评论”。
2. 在设置弹层中选择评论数量上限和采集深度。
3. 插件自动滚动评论区并展开回复。
4. 采集完成后写入本地。

成功结果：评论列表出现新数据。  
失败结果：页面提示失败原因，例如评论区不存在或加载异常。

## 4. 小红书批量采集流程

### 4.1 批量笔记

1. 在搜索页或博主页点击“批量采集笔记”。
2. 选择采集数量（`5 / 10 / 20 / 50`）和是否按点赞排序。
3. 插件先扫描页面，再逐篇打开笔记采集。
4. 任务进行中，页面右下角全局控制条可暂停/继续/停止。
5. 结束后显示成功/失败数量。

### 4.2 批量评论

1. 在搜索页或博主页点击“批量采集评论”。
2. 选择采集篇数。
3. 插件逐篇打开笔记并采集评论。
4. 用户可随时暂停、继续或停止。

## 5. 抖音单条视频与博主流程

### 5.1 当前视频采集

1. 进入抖音视频弹层页，或从博主页点开某条视频。
2. 点击“采集当前视频”，或点击抖音原生“分享”按钮。
3. 插件先确认当前视频上下文，再将当前视频写入本地。

成功结果：数据面板新增当前视频记录，标题、链接、视频 ID 与当前视频一致。  
失败结果：提示可读错误，不应默默采到上一条视频。

### 5.2 当前视频下载

1. 在当前视频点击“下载视频”。
2. 插件优先使用当前视频对应直链；必要时刷新 detail API 后再下载。

### 5.3 当前博主采集

1. 在抖音博主页点击“采集当前博主”。
2. 插件写入博主记录到本地。

## 6. 抖音当前视频评论流程

1. 在抖音视频弹层页点击“采集当前评论”。
2. 在设置弹层中选择评论上限与采集深度；留空或填 `0` 表示尽量采全量。
3. 插件针对当前视频采集一级评论和二级评论，并为这次动作创建单条评论任务上下文。
4. 评论数据写入本地，并保存父子层级关系。

成功结果：评论表里能明确看到这条视频的评论树。  
失败结果：提示可读错误，不应误采到别的视频。

## 7. 抖音当前视频评论图片区下载流程

1. 在抖音视频弹层页点击页内“评论图片区下载”，或在 Popup 中点击“评论图片区”。
2. 用户可设置评论扫描上限；留空或填 `0` 表示尽量扫描全部评论。
3. 插件先采集当前视频评论，再提取评论图片区高清候选链接并打包下载。
4. 扫描阶段显示的“已发现 X 张图片”和下载阶段的 `X/Y` 必须基于同一套唯一图片队列，不能在补采或去重后出现两套总数。
5. 下载结果写入 `mediaAssets`，用于后续分析与状态追踪。

成功结果：下载 ZIP 成功，且 `mediaAssets` 中能看到对应评论图片区状态。  
失败结果：提示可读错误，不应混入头像、表情和装饰图。
## 8. 抖音批量视频采集流程

1. 在抖音博主页或搜索页点击“批量视频”。
2. 选择数量（`5 / 10 / 20 / 50`）以及是否按点赞排序。
3. 插件请求当前页面对应的作品列表 API。
4. 若启用 Top N，会先尽量发现足够多的作品后再排序。
5. 再按选定顺序逐条写入本地。
6. 若来自搜索页，记录中同时保留搜索词与搜索页链接。

关键点：
- 该流程不依赖用户手动滑动页面。
- 数据进入面板后，后续应能再次下载视频。
- 运行中右下角应显示“抖音任务控制台”，不能回退成“小红书任务控制台”。

## 9. 抖音批量评论采集流程

1. 在抖音博主页或搜索页点击“批量评论”。
2. 在统一设置弹层中选择视频数量（`5 / 10 / 20`）、选取方式（当前顺位 / 点赞 Top N）、评论上限和采集深度。
3. 若上限留空，表示尽量采全量。
4. 若启用 Top N，会先尽量发现足够多的作品后再排序。
5. 插件先获取作品列表，再逐条拉评论接口和回复接口；必要时使用页面桥接兜底。
6. 若来自搜索页，评论记录与对应视频记录都应能看到搜索词关联。

成功结果：每条评论都能归属到对应视频，并保留层级。  
失败结果：某条视频失败不会阻断后续视频。
- 运行中右下角应显示“抖音任务控制台”，暂停 / 继续 / 停止都要命中抖音任务。

## 10. 数据面板流程

1. 在 Popup 点击”数据面板”打开 Dashboard。
2. 在”笔记/评论/博主”之间切换。
3. 支持搜索、筛选、按采集时间排序。
4. 支持导出 CSV / JSON。
5. **笔记勾选功能**：在笔记标签页可以勾选多个笔记，支持全选/取消全选
6. **批量操作**：`笔记 / 评论 / 博主` 三个标签页都支持批量导出、批量删除
7. **同步到内容工作台**：选中笔记、评论或博主后，都可以同步到内容工作台系统
8. 对抖音视频记录支持再次下载；若旧直链失效，插件应尽量先刷新 detail API 再下载。
9. 媒体预览：点击缩略图可预览大图或播放视频

## 11. 内容工作台远程任务流程

1. 用户在内容工作台创建 `pending` 采集任务。
2. 插件 Background 在启用工作台连接后定时轮询待执行任务。
3. 若当前浏览器存在匹配平台和页面上下文的 tab，插件先做能力检查，再自动认领任务；如果先撞上没真正接住插件的旧 tab，必须自动跳过并继续尝试下一张可执行页面，不能因为第一张坏页就整轮失败。
4. 小红书 `detail_probe` 任务如果已有带 `xsec_token` 的签名详情页，优先直开这条已验证可打开的入口，并直接调用“采集当前笔记”这条单篇采集链；如果拿到的是作者页卡片里的 `user/profile/.../noteId` 地址，则要改走“作者页接力”路径：先到对应作者主页根地址，只锁定这篇作品，再点开这篇作品做单篇采集，而不是继续新开那条可能触发 30017 的 relay 中转链接，也不是把整页当成普通批量列表。
5. 如果插件本地已经保存过这篇内容的签名分享链接，或者当前浏览器里已经开着同一篇内容页，派单应优先复用这条“已验证可打开”的入口，而不是再新开一条裸详情链接。
6. 插件只有在页内执行动作真正启动、并成功创建/绑定本地 `collectionRun` 后，才把这次派单视为“已启动成功”；不能把“消息发出去了但页面没开跑”误当成成功。
7. 运行过程中，插件持续把 `progress / pluginRunId / resultSummary / errorMessage` 回写给内容工作台。
8. 若任务已认领但长时间没有生成本地运行记录，插件必须自动把这类“假启动”任务标记为失败并释放，避免队列长期卡在 `dispatched`。
9. 任务结束后，内容工作台任务详情应能看到本次执行的结果摘要和最终状态。

当前阶段说明：
- 代码和单测已经覆盖该流程。
- 仍需一轮完整实机闭环，确认 `pending -> dispatched / running -> completed | failed` 在工作台 UI 中按预期推进。

## 12. 异常流程

### 12.1 验证码出现

1. 插件自动暂停任务。
2. 用户先手动通过验证码。
3. 用户选择“继续”或“停止”。

### 12.2 页面结构变化

1. 采集失败时给出可读报错。
2. 按 [SELECTORS.md](../SELECTORS.md) 和探查脚本复核选择器或页面信号。

## 13. Cookie & 账号管理流程

1. 用户切换到 Popup 的"数据"标签页，在"Cookie & 账号"区块点击"一键获取 Cookie"。
2. 插件从 Background 提取小红书和抖音的登录 Cookie（三级策略：cookies API → domain 查询 → content script document.cookie），并覆盖小红书根域名与子域名页面。
3. 提取结果显示为状态徽章（如"小红书 11 条 4/17 22:53"）。
4. 小红书 Cookie 自动保存为采集账号，出现在账号列表中。
5. 账号列表支持删除操作；也可通过"手动添加账号"弹窗手动粘贴 Cookie。若弹窗里的一键提取没有拿到小红书登录态，必须直接提示用户先打开并登录小红书，不能留下空 Cookie。
6. Cookie 持久化存储在 `chrome.storage.local`，插件各模块可随时通过 `MSG.GET_STORED_PLATFORM_COOKIES` 调取。
