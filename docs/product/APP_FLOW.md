# 灵感爆爆爆 — 用户操作流程

> 关联文档：[BEGINNER_GUIDE.md](BEGINNER_GUIDE.md) · [PRD.md](PRD.md) · [TEST_CHECKLIST.md](TEST_CHECKLIST.md)

## 1. 主流程总览

1. 用户打开小红书或抖音页面。
2. Popup 顶部采用紧凑双列头部：左侧品牌区垂直居中显示长条品牌 banner；右侧上方提供平台/主题切换，下方显示较小的产品名，再进入当前平台和页面场景说明，告诉用户此页适合执行什么任务。
3. 用户在“当前内容 / 批量任务 / 工具区”中选择对应动作。
4. 所有主按钮点击后都要立即进入忙碌态：显示旋转指示或“执行中 / 获取中 / 导出中”，并临时禁用重复点击。
5. 任务状态卡统一显示准备中、扫描中、下载中、暂停中等阶段。
6. 页内长任务会使用统一的右下任务控制台和顶部通知条，避免平台之间出现两套完全不同的反馈方式；其中控制台卡片结构统一，但平台标题与按钮动作必须跟随当前站点。
7. 采集完成后，在 Dashboard 中查看、筛选、导出或再次下载媒体；若列表为空，必须明确区分“还没数据”和“筛选后无结果”。
8. 若已启用内容工作台连接，且当前浏览器已经完成“插件授权 + 执行工位配对”，插件还会在 Background 中轮询可执行的 `pending` 采集任务，并在匹配页面上自动接单。

## 2. 小红书单篇笔记采集流程

1. 进入笔记详情页，点击“采集笔记”。
2. 插件读取笔记内容和媒体链接并保存到本地。
3. 插件提示是否下载媒体文件，并允许勾选封面、所有图片、Live 或视频。
4. 用户确认后，插件按所选类型逐个下载；若旧视频链接失效，插件会先刷新媒体链接后再重试。

成功结果：页面提示采集成功，数据面板出现新记录。  
失败结果：页面提示采集失败，并显示可读错误信息。

## 3. 小红书单篇评论采集流程

1. 进入笔记详情页，点击“采集评论”。
2. 在设置弹层中选择评论数量上限和采集深度。
3. 插件自动滚动评论区并展开回复。
4. 采集完成后写入本地。

成功结果：评论列表出现新数据。  
失败结果：页面提示失败原因，例如评论区不存在或加载异常。

## 4. 小红书博主页动作流程

### 4.1 当前博主采集

1. 在小红书博主页打开 Popup，点击“采集当前博主”。
2. 插件读取当前博主主页信息并写入本地。

成功结果：博主列表出现这位博主，名称、小红书号、粉丝、关注、互动数可见。  
失败结果：提示当前不是有效博主页，或主页信息读取失败。

### 4.2 批量笔记

1. 在搜索页或博主页点击“批量采集笔记”。
2. 弹层会根据平台、页面场景和最近一次操作给出智能默认值，例如默认篇数、Top N 开关与最近一次使用的设置。
3. 用户可继续调整采集数量（`5 / 10 / 20 / 50`）和是否按点赞排序。
4. 插件先扫描页面，再逐篇打开笔记采集。
5. 任务进行中，页面右下角全局控制条可暂停/继续/停止。
6. 若用户主动停止任务，必须先经过确认弹层，再终止当前批量流程。
7. 结束后显示成功/失败数量。

### 4.3 批量评论

1. 在搜索页或博主页点击“批量采集评论”。
2. 弹层根据平台、页面场景和历史偏好自动预填采集篇数、评论上限与采集深度。
3. 插件逐篇打开笔记并采集评论。
4. 用户可随时暂停、继续或停止；停止前必须二次确认。

## 5. 抖音单条视频与博主流程

### 5.1 当前视频采集

1. 进入抖音视频弹层页，或从博主页点开某条视频。
2. 点击“采集当前视频”，或点击抖音原生“分享”按钮。
3. 插件先确认当前视频上下文，再将当前视频写入本地。

成功结果：数据面板新增当前视频记录，标题、链接、视频 ID 与当前视频一致。  
失败结果：提示可读错误，不应默默采到上一条视频。

### 5.2 当前视频下载

1. 在当前视频点击“下载视频”。
2. 插件优先使用当前视频对应直链；必要时刷新 detail API 后再下载。

### 5.3 当前博主采集

1. 在抖音博主页点击“采集当前博主”。
2. 插件写入博主记录到本地。

## 6. 抖音当前视频评论流程

1. 在抖音视频弹层页点击“采集当前评论”。
2. 在设置弹层中选择评论上限与采集深度；留空或填 `0` 表示尽量采全量。
3. 插件针对当前视频采集一级评论和二级评论，并为这次动作创建单条评论任务上下文。
4. 评论数据写入本地，并保存父子层级关系。

成功结果：评论表里能明确看到这条视频的评论树。  
失败结果：提示可读错误，不应误采到别的视频。

## 7. 抖音当前视频评论图片区下载流程

1. 在抖音视频弹层页点击页内“评论图片区下载”，或在 Popup 中点击“评论图片区”。
2. 用户可设置评论扫描上限；留空或填 `0` 表示尽量扫描全部评论。
3. 插件先采集当前视频评论，再提取评论图片区高清候选链接并打包下载。
4. 扫描阶段显示的“已发现 X 张图片”和下载阶段的 `X/Y` 必须基于同一套唯一图片队列，不能在补采或去重后出现两套总数。
5. 下载结果写入 `mediaAssets`，用于后续分析与状态追踪。

成功结果：下载 ZIP 成功，且 `mediaAssets` 中能看到对应评论图片区状态。  
失败结果：提示可读错误，不应混入头像、表情和装饰图。
## 8. 抖音批量视频采集流程

1. 在抖音博主页或搜索页点击“批量视频”。
2. 选择数量（`5 / 10 / 20 / 50`）以及是否按点赞排序。
3. 插件请求当前页面对应的作品列表 API。
4. 若启用 Top N，会先尽量发现足够多的作品后再排序。
5. 再按选定顺序逐条写入本地。
6. 若来自搜索页，记录中同时保留搜索词与搜索页链接。

关键点：
- 该流程不依赖用户手动滑动页面。
- 数据进入面板后，后续应能再次下载视频。
- 运行中右下角应显示“抖音任务控制台”，不能回退成“小红书任务控制台”。

## 9. 抖音批量评论采集流程

1. 在抖音博主页或搜索页点击“批量评论”。
2. 设置弹层只保留一句场景说明和核心参数，避免大段解释干扰操作。
3. 用户选择视频数量（`5 / 10 / 20`）、选取方式（当前顺位 / 点赞 Top N）、评论上限和采集深度。
4. 若评论上限留空，表示尽量采全量。
5. 若启用 Top N，会先尽量发现足够多的作品后再排序。
6. 插件先获取作品列表，再逐条拉评论接口和回复接口；必要时使用页面桥接兜底。
7. 若来自搜索页，评论记录与对应视频记录都应能看到搜索词关联。

成功结果：每条评论都能归属到对应视频，并保留层级。  
失败结果：某条视频失败不会阻断后续视频。
- 运行中右下角应显示“抖音任务控制台”，暂停 / 继续 / 停止都要命中抖音任务。

## 10. 数据面板流程

1. 在 Popup 点击”数据面板”打开 Dashboard。
2. 顶部头部只保留长条品牌 `banner` 与右侧 tab，不再显示方形 logo 或额外标题行。
3. 在”笔记/评论/博主”之间切换。
4. 支持搜索、筛选、按采集时间排序。
5. 支持导出 CSV / JSON。
6. **笔记勾选功能**：在笔记标签页可以勾选多个笔记，支持全选/取消全选
7. **批量操作**：`笔记 / 评论 / 博主` 三个标签页都支持批量导出、批量删除
8. **同步到内容工作台**：选中笔记、评论或博主后，都可以同步到内容工作台系统
9. 对小红书和抖音记录支持再次下载媒体；点击“媒体”后先选择封面、所有图片、Live 或视频，再只下载选中的类型。若旧直链失效，插件应尽量先刷新当前媒体链接再下载。
10. 媒体预览：点击缩略图可预览大图或播放视频

## 11. 内容工作台授权与配对流程

1. 管理员在内容工作台“设置 → 插件授权”里生成授权码，并指定成员 / 席位 / 有效期。
2. 使用人在插件配置页先选择工作台地址；插件内置“线上正式站 `https://lingganboom.fun`”和“本地 3000 `http://localhost:3000`”两个快捷入口，并会记住最近一次选择。确认地址后，再输入授权码，激活当前浏览器的插件使用资格。
3. 授权成功后，插件开放采集、导出、同步、Cookie/账号管理和执行工位绑定。
4. 普通同步到内容工作台前，插件会绑定当前登录的内容工作台使用者账号；数据写入这个使用者自己的数据空间，不写入授权码创建者账号。
5. 若该浏览器还需要接工作台远程任务，则继续输入配对码，绑定手动工位或监控工位。
6. 内容工作台后续可随时撤销授权；插件在下一次心跳、接单、同步时必须立即失效并要求重新激活授权码。

## 12. 内容工作台远程任务流程

1. 用户在内容工作台创建 `pending` 采集任务。
2. 插件 Background 只有在“工作台地址已配置 + 插件已授权 + 执行工位已配对”后，才定时轮询待执行任务。
3. 若当前浏览器存在匹配平台和页面上下文的 tab，插件先做能力检查，再自动认领任务；如果先撞上没真正接住插件的旧 tab，必须自动跳过并继续尝试下一张可执行页面，不能因为第一张坏页就整轮失败。
4. 若可执行页面只剩“用户当前正在看的那张前台页”，插件不应直接劫持这张页开跑，而是改在独立执行窗口里打开任务页，尽量不打断当前浏览。
5. 小红书 `detail_probe` 任务如果已有带 `xsec_token` 的签名详情页，优先直开这条已验证可打开的入口，并直接调用“采集当前笔记”这条单篇采集链；如果拿到的是作者页卡片里的 `user/profile/.../noteId` 地址，则要改走“作者页接力”路径：先到对应作者主页根地址，只锁定这篇作品，再点开这篇作品做单篇采集，而不是继续新开那条可能触发 30017 的 relay 中转链接，也不是把整页当成普通批量列表。
6. 如果插件本地已经保存过这篇内容的签名分享链接，或者当前浏览器里已经开着同一篇内容页，派单应优先复用这条“已验证可打开”的入口，而不是再新开一条裸详情链接。
7. 插件只有在页内执行动作真正启动、并成功创建/绑定本地 `collectionRun` 后，才把这次派单视为“已启动成功”；不能把“消息发出去了但页面没开跑”误当成成功。
8. 小红书 `author_baseline` 首次建档会先采博主，再按当前博主页顺位补前 50 篇作品；作品记录应尽量带封面，详情页缺图时用博主页卡片封面兜底；整条链路都跑完后，任务才算完成。
9. 运行过程中，插件持续把 `progress / pluginRunId / resultSummary / errorMessage` 回写给内容工作台。
10. 若任务已认领但长时间没有生成本地运行记录，插件必须自动把这类“假启动”任务标记为失败并释放，避免队列长期卡在 `dispatched`。
11. 如果打开任务目标后发现笔记已删除、页面错误或当前账号无权限访问，插件必须把任务标记为失败并保留页面自检摘要，不允许退回 `pending` 反复派给其他工位。
12. 任务结束后，内容工作台任务详情应能看到本次执行的结果摘要和最终状态。

当前阶段说明：
- 代码和单测已经覆盖该流程。
- 仍需一轮完整实机闭环，确认 `pending -> dispatched / running -> completed | failed` 在工作台 UI 中按预期推进。

## 13. 异常流程

### 13.1 验证码出现

1. 插件自动暂停任务。
2. 用户先手动通过验证码。
3. 用户选择“继续”或“停止”。

### 13.2 页面结构变化

1. 采集失败时给出可读报错。
2. 按 [SELECTORS.md](../SELECTORS.md) 和探查脚本复核选择器或页面信号。

## 14. Cookie & 账号管理流程

1. 用户切换到 Popup 的"数据"标签页，在"Cookie & 账号"区块点击"获取当前平台 Cookie"。
2. 插件只抓取当前页面所在平台的登录 Cookie：小红书页只抓小红书，抖音页只抓抖音；抓取策略仍为 cookies API → domain 查询 → content script `document.cookie`。
3. 结果只显示当前平台的状态卡，并以紧凑状态徽章呈现（如"小红书 11 条 4/17 22:53"）；未登录时要明确显示失败原因。
4. 小红书 Cookie 成功抓取后自动保存为采集账号，出现在账号列表中；抖音页抓取时不应误新增小红书账号。
5. 账号列表支持删除操作，删除前需要确认；也可通过"手动添加账号"弹窗手动粘贴 Cookie。若弹窗里的一键提取没有拿到小红书登录态，必须直接在弹窗内提示用户先打开并登录小红书，不能留下空 Cookie。
6. Cookie 持久化存储在 `chrome.storage.local`，插件各模块可随时通过 `MSG.GET_STORED_PLATFORM_COOKIES` 调取。

## 15. 统一交互反馈流程

1. Popup Notice、Dashboard 顶部通知条与页内 Toast 共享同一套语义：标题 + 正文 + 图标 + 颜色。
2. 危险动作统一走确认弹层，包括停止批量任务、删除账号、删除单条数据、批量删除与清空数据。
3. 状态颜色编码统一：成功/完成为绿色，处理中/信息为蓝色，待处理/提醒为黄色，失败/阻断为红色，中性说明为灰色。
4. 空状态要告诉用户“为什么没有内容”和“下一步该做什么”，不能只留一块空白。
