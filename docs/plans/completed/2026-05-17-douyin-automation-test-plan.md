## 3. 测试分层

### 3.1 第一层：代码级回归

目标：每次改代码后快速判断核心逻辑有没有坏。

覆盖范围：

- 抖音详情字段解析。
- 抖音搜索结果发现。
- 抖音批量采集排序与节奏。
- 抖音安全验证暂停。
- 评论与二级/多级回复采集。
- 评论图片区高清候选源。
- 数据面板二次下载，含抖音视频/图文图片下载降级。
- 工作台远程任务接单、暂停/继续/停止控制与回写。
- 工作台能力检查在页面未加载插件时返回可读的 `page_context_unavailable`，避免远程任务被不明原因卡住。
- 版本脚本同步 `package.json`、`package-lock.json`、`manifest.json`，并生成可校验安装包。
- 发布校验会比对 zip 内关键文件与当前 `dist/` 文件，防止版本号正确但安装包内容滞后。

验收方式：

```bash
npm run verify:douyin
```

通过标准：

- 测试全部通过。
- 构建成功。
- 只允许出现既有体积提示，不允许出现构建失败。

### 3.2 第二层：真实网页冒烟测试

目标：确认插件在真实抖音页面上还能识别当前内容。

覆盖范围：

- 抖音搜索页是否有结果。
- 抖音视频页是否能识别当前视频。
- 抖音博主页弹层是否能识别当前弹层视频。
- 当前视频 ID、标题、作者、链接是否一致。
- 页面是否出现安全验证或登录拦截。

通过标准：

- 页面有真实内容结果。
- 不被登录页、安全验证页挡住。
- 当前视频识别不串到上一条或下一条。

### 3.3 第三层：插件功能冒烟测试

目标：确认用户可见功能能用。

覆盖范围：

- 页面右侧按钮是否出现。
- 点击采集视频后，数据面板出现 `dy_` 前缀记录。
- 点击下载媒体后，视频或图片能下载。
- 点击采集评论后，评论能保存，并绑定当前视频。
- 点击评论图片区后，只下载评论图片，不混入头像或装饰图。
- 批量视频和批量评论能暂停、继续、停止。

通过标准：

- 用户能看见明确的成功提示。
- 数据面板能看到记录。
- 下载文件能打开。
- 失败时有可读原因，而不是静默失败。

### 3.4 第四层：工作台任务链路测试

目标：确认内容工作台派单后，插件能作为执行工位稳定接单。

覆盖范围：

- 插件授权有效。
- 工位绑定有效。
- 任务能被接走。
- 任务状态从等待、执行中，到成功或失败。
- 失败原因能回写。
- 安全验证时任务暂停，而不是误报完成。

通过标准：

- 工作台能看到任务生命周期。
- 任务结果能回写到对应数据表。
- 失败可重试，且原因可读。

顺序：

1. 单条视频采集。

4. 评论图片区下载。
