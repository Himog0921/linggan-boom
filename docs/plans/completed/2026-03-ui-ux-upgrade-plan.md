# 2026-03 插件 UI/UX 升级整理计划

> 目标：把“功能可用”推进到“非技术用户也能快速理解、稳定操作、低心智负担”  
> 范围：Popup、Dashboard、小红书页内注入、抖音乐内注入、任务条、弹层、通知、批量设置、评论图片区与长任务体验  
> 方法：先审查信息架构与任务语义，再做共享组件化和逐面升级  
> 依据：项目当前真实代码 + `Build Web Apps` Web Interface Guidelines

---

## 1. 现状判断

当前插件已经基本具备完整的采集、批量、评论、评论图片区、数据面板与导出能力，但 UI/UX 还停留在“工程师能用、用户也能勉强学会”的阶段，主要问题不是某一个页面不好看，而是：

1. **状态反馈分散**
   - 顶部红条
   - 卡片附近小浮层
   - 底部进度条
   - 右下角任务控制台
   - Popup 通知条
   - Dashboard 通知条
   这些反馈点都有意义，但同时存在时容易冲突、重复、遮挡。

2. **任务语义不够统一**
   - 单条任务与批量任务的“暂停 / 继续 / 停止”语义不完全一致
   - 评论采集、评论图片区、批量评论、批量视频的状态提示风格不一致
   - “扫描阶段 / 下载阶段 / 打包阶段”的界限对用户不够清晰

3. **信息密度偏高，但层级不够明确**
   - Popup 现在把统计、单条操作、批量操作、维护、导出都放在一个面上
   - Dashboard 列很多，但没有形成“分析优先级层级”
   - 页内注入按钮在不同页面的布局虽然已分流，但品牌、动作、状态仍偏“工具条思维”

4. **跨平台体验不完全对齐**
   - 抖音、小红书用户操作场景相似，但一些动作的反馈和引导方式不同
   - 用户不应该为“平台技术差异”付出额外学习成本

5. **可访问性与细节还有提升空间**
   - 搜索框、筛选器、批量设置等控件还存在“主要靠视觉理解”的情况
   - 表格和任务反馈的可读性、可扫描性可以继续提升

## 2. 当前 UI 面清单

### 2.1 Popup

文件：
- `src/popup/popup.html`
- `src/popup/popup.css`
- `src/popup/popup.js`

职责：
- 平台识别
- 数据概览
- 单条采集入口
- 批量任务入口
- 数据面板 / 导出 / 数据维护入口

当前问题：
- 主次动作太多，第一屏决策成本偏高
- 单条与批量的关系不够一眼看懂
- 统计卡片、主按钮、底部工具按钮都很抢注意力

### 2.2 Dashboard

文件：
- `src/dashboard/dashboard.html`
- `src/dashboard/dashboard.css`
- `src/dashboard/dashboard.js`

职责：
- 数据浏览
- 搜索筛选
- 导出
- 二次下载
- 删除

当前问题：
- 信息密度高，但表格层级和列优先级还不够明显
- 当前更像“全量原始数据表”，而不是“面向分析的管理面板”
- 跨平台字段已经很多，需要更好的分组/可见性策略

### 2.3 小红书页内注入

文件：
- `src/platforms/xhs/uiInjector.js`

职责：
- 笔记详情页操作
- 搜索/主页批量入口
- 任务控制条
- 评论/评论图片区设置弹层

当前问题：
- 批量入口和单条入口的风格一致，但任务状态与当前页面上下文关系不够明确
- 小红书批量笔记的“当前卡片高亮”价值不高，应该弱化或移除

### 2.4 抖音页内注入

文件：
- `src/platforms/douyin/uiInjector.js`
- `src/platforms/douyin/index.js`

职责：
- 视频详情操作
- 搜索/主页批量入口
- 当前作品提示
- 任务控制台
- 评论/评论图片区设置弹层

当前问题：
- “当前作品提示”与控制面板、任务条之间仍有重复感
- 抖音搜索页、详情页、主页弹层的场景切换虽然功能上已分流，但 UI 还没完全把“此处能做什么 / 不能做什么”说清楚
- 抖音搜索结果页的页内入口必须显式区分“搜索结果批量采集”与“博主页批量采集”，否则即使底层链路正确，用户也会因为对话框文案和任务阶段 badge 错位而误判功能已卡死

## 3. 升级目标

### 目标 A：统一任务体验

让用户在任何地方都能理解：
- 我现在是在执行什么任务
- 这个任务在哪个阶段
- 是否可以暂停/继续/停止
- 停止后会保留什么结果

### 目标 B：降低首次使用成本

让新用户不需要读太多说明，也能快速理解：
- 单条采集 vs 批量采集
- 评论采集 vs 评论图片区
- 详情页可执行什么，搜索页可执行什么，主页可执行什么

### 目标 C：提升数据面板可读性

让 Dashboard 更像“数据工作台”，而不是“原始字段堆叠表”。

### 目标 D：跨平台体验对齐

在不牺牲稳定性的前提下，让小红书和抖音的任务模型尽量一致：
- 入口一致
- 状态一致
- 控制方式一致
- 文案一致

---

## 4. 升级原则

1. **一个任务，只保留一个主状态面。**
   - 避免同一时刻顶部、底部、右下、卡片旁都在重复同一种信息。

2. **先做信息架构，再做视觉。**
   - 不是先换颜色、换圆角，而是先决定：哪些信息应该在第一层，哪些应该折叠。

3. **用“阶段”解释长任务。**
   - 特别是评论采集、评论图片区、批量任务。

4. **平台差异藏在实现里，不暴露给用户。**
   - 用户不需要理解 DOM、API、详情页/弹层，只需要理解“这里现在能不能做这件事”。

5. **能固定的交互，不做漂浮式复杂提示。**
   - 当前卡片高亮、局部浮层等能力应谨慎使用，优先固定任务条和稳定通知区。

## 5. 分阶段升级路线

### Wave UI-1：信息架构收口

目标：
- 重新定义 Popup、页内按钮、任务控制条、Dashboard 的职责边界

任务：
1. Popup 重构为三层：
   - 当前页面上下文
   - 主动作区
   - 工具区
2. 页内注入按钮按页面类型做明确分组：
   - 详情页：单条动作优先
   - 搜索/主页：批量动作优先
3. 统一任务状态模型：
   - 准备中
   - 扫描中
   - 下载中
   - 打包中
   - 已暂停
   - 已停止
   - 已完成

完成标志：
- 用户第一次打开 Popup，不会被一堆同级按钮淹没
- 单条/批量/评论图片区状态文案统一

### Wave UI-2：共享视觉系统

目标：
- 把当前“品牌感有了，但局部控件仍不够统一”的状态，收成共享规则

任务：
1. 抽共享设计 token：
   - 主色
   - 辅色
   - 危险色
   - 成功色
   - 阴影
   - 边框
   - 圆角
2. 统一按钮层级：
   - Primary
   - Secondary
   - Outline
   - Danger
3. 统一弹层和通知条样式
4. 统一任务控制台尺寸和信息区布局

完成标志：
- Popup / Dashboard / 页内注入不再像三套独立产品

### Wave UI-3：任务体验优化

目标：
- 长任务不再“功能上有了，体验上还是像调试工具”

任务：
1. 统一评论采集深度选择对话框
2. 评论图片区下载改成真正的“两阶段心智模型”
3. 单条评论与批量评论共享同一控制语义
4. 停止/暂停/继续后的反馈文案统一

完成标志：
- 用户能在不懂技术的情况下理解停止后会发生什么

### Wave UI-4：Dashboard 数据可读性升级

目标：
- 从原始表格进化成更适合分析与回看的工作台

任务：
1. 区分“核心列”和“扩展列”
2. 优化跨平台字段命名一致性
3. 优化评论层级展示
4. 优化媒体预览与下载动作的表达
5. 清理内容噪音（如多余 `#`、占位值、无意义字段）

完成标志：
- 用户在 Dashboard 里更容易看懂“这是什么数据、它和什么内容关联”

### Wave UI-5：可访问性与文案精修

目标：
- 达到稳定、清晰、低歧义的插件级产品体验

任务：
1. 为搜索、筛选、设置弹层补完整 label / aria 语义
2. 统一错误提示：
   - 说清问题
   - 说清下一步怎么做
3. 统一平台文案：
   - “视频 / 笔记 / 内容”
   - “批量视频 / 批量笔记 / 批量评论”
4. 统一中文文案风格与任务命名方式

完成标志：
- 不再需要靠内部语义和技术暗示让用户猜

## 6. 当前优先级建议

如果下一轮正式开始做 UI/UX，我建议按这个顺序：

1. **先做 Popup 信息架构和任务状态统一**
2. **再做页内任务条和通知系统统一**
3. **再做 Dashboard 的表格层级和分析可读性**
4. **最后统一视觉 token 和文案**

原因：
- 先改结构，收益最大
- 先改用户理解，再改视觉风格
- 先改任务流，再改品牌表达

## 7. 验收标准

这轮 UI/UX 升级只有同时满足下面条件才算成功：

1. 新用户首次打开 Popup，能在 5 秒内理解当前页能做什么
2. 单条任务和批量任务的状态与控制方式统一
3. 评论采集和评论图片区的阶段语义清晰
4. Dashboard 的主要字段在不解释的情况下基本可读
5. 抖音与小红书的相同任务，在交互上尽量同构
6. 不引入新的页面遮挡、重叠和误触问题
